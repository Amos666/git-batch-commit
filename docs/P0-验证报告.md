### P0-2 提交选项最小集 + 消息历史

- `commit.show`：结果面板"查看提交" → `DiffService.openCommit` → 多文件 Diff（`vscode.changes`，失败回退单文件 `vscode.diff`）。
- 文件清单获取按 API 版本分层（见 F8）：`diffBetweenWithStats2(range)` 优先（根提交用 `<oid>^!`）→ `diffBetweenPatch(parent, oid)` → 文档版 `diffBetween`（兼容 string 与解析数组两种返回）。

## 3. 新增发现（F8–F11）

### F8. 内置 Git API 的 diffBetween 家族与文档漂移（重要）
实测 stable 1.146.0 的 `extensions/git/dist/main.js`：
- `diffBetween(ref1, ref2)` 不再返回 patch 字符串，而是 `git diff --name-status -z ref1...ref2` 的**解析数组**，且内部固定**三点**区间；
- `diffBetweenPatch(ref1, ref2, path?)` 同样构造三点区间；
- `diffBetweenWithStats(EMPTY_TREE, oid)` 的空树特判**上游失效**：`_EMPTY_TREE` 是 async getter，`e === this._EMPTY_TREE` 恒为 false（字符串与 Promise 比较），永远走三点分支 → 根提交必失败；
- **可用出口**：`diffBetweenWithStats2(range, path?)` 原样透传 range 字符串 → 用 `parent..oid` / `<oid>^!` 即可覆盖根提交。
对策：`commitFilePaths` 三级降级（stats2 → patch → 文档版 diffBetween），类型契约标注可选方法。P1 若做日志/对比视图，优先 stats2。

### F9. 本机 git 为裁剪构建
`git --exec-path` 目录不存在，`git submodule`（shell 脚本）缺失；worktree/clone 等内建命令可用。夹具改用 `clone + .gitmodules + update-index --cacheinfo 160000` 手工构造 submodule，内置扩展识别 kind 正常。CI 若用完整 git 可换回 `submodule add`。

### F10. 确认门重入缺陷（已修复）
跳过钩子确认条的"确认跳过"最初调用无参 `commit()`，会再次触发确认门形成死循环；且 `skipHooksRetry` 路径未强制 `noVerify:true`。修复：`commit({confirmed:true, noVerify:true})`，`noVerify` 支持 opts 覆盖。

### F11. 根提交 Diff 左侧呈现限制
根提交的多文件 Diff 左侧用空树 ref（`toGitUri(file, EMPTY_TREE)`），git 内容提供者对"空树中不存在的路径"会显示解析错误占位而非空白。语义正确（新增文件），呈现略糙；P1 可改为空白虚拟文档。
