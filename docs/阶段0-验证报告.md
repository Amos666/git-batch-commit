
已实现的核心语义（与方案 §4.1 一致）：

- **勾选 = 暂存**：checkbox 翻转 → `add` / `restore({staged:true})`，乐观更新 + `state.onDidChange` 回灌校准；
- **提交 = `commit({all:false})`** 只提交 index；提交前 `expectedStaged` 一致性校验；
- **多仓库顺序编排**：默认失败即停、结果聚合（成功/失败/跳过）、"取消后续仓库"、幂等防重复；
- **错误三层呈现**：GitErrorCodes → 摘要 + 恢复动作 + `git.showOutput` + 终端重试（白名单命令、不自动回车）；
- **前置校验**：空消息 / 空暂存区 / 未解决冲突均在发起 git 前拦截；
- 首次加载 tracked 自动暂存（`defaultSelectAll`，未跟踪默认不选）；
- 分支胶囊（detached/ahead/behind）+ 分支列表切换；三向 Diff；状态事件去抖 + seq。

## 3. 关键发现（影响后续阶段）

| # | 发现 | 影响与处置 |
|---|---|---|
| F1 | **提交后 `state.HEAD` 可能滞后**：内置状态刷新是异步的，commit 返回瞬间读 HEAD 可能拿旧 oid | 已修复：提交成功后用 `repo.getCommit('HEAD')` 显式取新 oid（集成测试验证 oid 新鲜）。P0 所有"操作后读状态"的路径都要注意此模式 |
| F2 | **抛出的 GitError 对象上实际带有 stderr/gitCommand 等字段**（git.d.ts 未完整声明）：钩子失败文本经 `err.stderr ?? err.message` 成功归类 HOOK_FAILED | 风险 R5（无 stderr）部分缓解：错误对象上的 stderr 经验可用，但**非公开契约**，P1 可做详情增强，必须保留"查看 Git 输出 + 终端重试"兜底，不能依赖 |
| F3 | 钩子失败**无专门 GitErrorCode**，靠 stderr 正则识别 | 与方案预判一致；正则需持续收集真实钩子输出样本（P0 测试矩阵扩充） |
| F4 | 本机 `git init` 不生成 `.git/hooks` 目录（环境特性） | fixture 脚本已 mkdir 兜底；提示：不同环境 git 模板差异需进兼容矩阵 |
| F5 | **首次加载自动暂存 tracked 是有副作用的设计**（打开面板即写 index）：符合已确认验收用例 10，但会覆盖用户"刻意保持未暂存"的状态 | P0 需复核交互：候选改为"默认勾选但不写 index、提交时按勾选集构造"或保留现状+设置开关。已列为 P0 首个待复核项 |
| F6 | `getAPI(1)` 在当前 VS Code stable 上契约稳定，激活/初始化等待/事件桥全部按文档工作 | 路线 A 核心假设成立 |
| F7 | 进行中操作不可中断（API 限制）再次确认；"取消后续仓库"逻辑已实现 | 慢钩子场景的取消时序未自动化（需 sleep 钩子 fixture），P0 补 |

## 5. 人工验证步骤（Webview UI 无法无头验证）

```bash
cd git-batch-commit
npm install && npm run build
# 用 VS Code 打开本目录，按 F5（Run Extension）
# 在扩展开发宿主中打开任意 git 仓库文件夹 → 活动栏 "Git Batch Commit" 图标
```

检查点：面板渲染/主题变量、勾选即时翻转与回灌、Diff 三向标题、分支切换、提交结果与错误动作按钮、禁用原因提示、Ctrl+Enter。
