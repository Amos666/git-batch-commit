## 1. 目标与边界

### 1.1 目标

在 VS Code 中提供与 IDEA Git 提交体验**行为一致**的工作台：

- 批量勾选文件一次提交；Changes / Staged / Untracked / Conflicted 清晰分组；
- 文件级 Diff（HEAD ↔ index ↔ worktree 三向），Hunk 级暂存（P1）；
- 面板内分支胶囊（分支名 / detached / ahead / behind）、切换分支；
- 多行提交消息、历史、模板、Amend、Commit & Push；
- 多仓库（multi-root / 嵌套 / worktree / submodule）正确归组与批量编排；
- 提交进度、取消后续仓库、逐仓库结果与可操作的失败原因；
- 大仓库不卡顿、不重复提交、不丢用户选择。

### 1.2 "1:1" 的定义

**任务语义与操作路径一致**，不是 Swing 像素级复刻：

- 分裂按钮 + 下拉执行器、Ctrl/Cmd+Enter、勾选包含模型、右键菜单对应存在；
- "Commit 只提交 included/已暂存内容" 语义必须一致；
- 视觉遵循 VS Code 设计语言（主题变量、Codicon），不携带 JetBrains 品牌资产；
- IDEA 弹窗文化转译为 VS Code 习惯：选项面板在 Webview 内自绘（保持一屏多选项），确认用模态通知，分支选择用 QuickPick。

### 1.3 非目标（首版不做）

- 不替代内置 SCM（并存互操作，不抢占 `git.*` 命令）；
- 交互式 rebase 全流程、bisect、filter-repo、LFS 专属 UI、submodule 递归更新 UI；
- 自建 Git 进程执行层（仅 P1 MiniRunner 白名单例外）；
- AI 提交消息生成、完整 blame、Log 工具窗口全量复刻、商业化。

### 1.4 P0 验收定义（不看文档即可完成）

1. 含 2 个仓库的工作区打开提交面板；
2. 看到按仓库分组的变更，勾选 3 个文件，查看其中 2 个的 Diff；
3. 输入消息，Ctrl+Enter 提交；
4. 看到每个仓库的成功/失败结果，ahead 数更新；
5. 全程 UI 不冻结；可"取消后续仓库"；进行中操作不可中断但可靠返回结果；
6. 重复点击不产生第二个 commit。

## 3. 核心分析结论汇总（各文档要点）

### 3.1 IDEA 提交体系拆解（可行性报告 §2）

IDEA 体验 = 三层可独立实现的抽象：

1. **包含模型**：哪些文件/仓库参与本次提交（included set）；
2. **提交流程状态机**：校验 → checks → 执行 → 进度 → 结果聚合；
3. **Git 命令构造器**：消息经文件/stdin 传递（绝不 `-m` 拼接）、选项参数化、错误分类检测。

必须对齐的提交语义：普通提交只提交已暂存；Commit All 只含 tracked（`add -u`），未跟踪需显式 add；空提交默认阻止；amend 已推送需警告且不自动强推；失败逐仓库聚合不假装全成功；提交成功清空消息（可配置）、刷新失败不回滚提交。

### 3.2 内置 Git 扩展可复用能力（架构对比 §3，路线 A 的依据）

| 能力 | 内置实现 | 我们获得 |
|---|---|---|
| 进程治理 | spawn 参数数组、stdin 丢弃、`LC_ALL/GIT_PAGER` 注入 | 免费，无注入/挂起风险 |
| 认证 | askpass 脚本 + IPC 回连 + 原生 InputBox，终端同注入 | 后台 git 永不等待终端输入 |
| 锁冲突 | `RepositoryIsLocked` 二次退避重试 10 次 | 免费 |
| 状态解析 | `status -z`（NUL 分隔）+ 流式解析 + 1 万条上限 kill + 大仓库警告 | 免费，特殊文件名安全 |
| 并发 | OperationManager 每仓库写操作串行 + `@throttle` 去抖 | 不自建进程锁 |
| watcher | `.git` + 工作区 + upstream ref → status | 不自建 watcher |
| 仓库发现 | 多根/嵌套/worktree/submodule/Workspace Trust | 免费 |
| 乐观更新 | 提交前清空组，UI 即时反馈 | 交互模式参照 |
| 对外 API | `getAPI(1)`：repositories、state 四组变更、commit/add/restore/push/checkout/stash/log/diff/buffer/show、事件、CredentialsProvider 等扩展点 | 提交语义绝大部分已可编程 |

**API 缺口清单（自建层的边界）**：

1. 不透出 stderr → 错误码 + `git.showOutput` + 终端重试兜底；
2. 无进行中操作的 CancellationToken → 只能"取消后续仓库"；
3. 无 stash 列表查询 → MiniRunner `git stash list`（P1）；
4. 无行级/Hunk 级暂存原语 → MiniRunner `hash-object` + `update-index`（P1）；
5. 无 Shelf/Changelist → P2 自建存储层。

### 3.3 GitJet 十大缺陷（反面教材，验收用例来源）

| 编号 | 缺陷 | 我们的对策 |
|---|---|---|
| D1 | execFile 无超时/取消/stdin 治理 → 永久悬挂 | 路线 A 全走内置 API（askpass 消灭等输入） |
| D2 | Webview 10s 硬超时但后台继续跑 → UI 与真实操作分裂 | **不设统一超时**；请求必达（成功/失败），进度事件带 seq |
| D3 | 提交无按仓库串行 → 重复点击并发 commit | 内置 OperationManager + UI 层幂等禁用 |
| D4 | 多仓库聚合显示但只用第一个 service 提交 | `repoId` 全链路（协议/缓存/diff/选择集） |
| D5 | add 选中后提交整个 index → 多提交未勾选内容 | checkbox=staged 强一致 + 提交前 expectedStaged 校验 |
| D6 | 首次加载零勾选 + 按钮无解释变灰 | tracked 默认全选；禁用必须显示原因 |
| D7 | status 按 `\n` 切分 → 特殊文件名解析错 | 内置 `status -z` 免费解决 |
| D8 | amend 后自动 `--force-with-lease` | 强推仅显式 + 二次确认 |
| D9 | stderr 直透、无恢复动作 | 错误码 → 一句话摘要 + 动作按钮 + 终端兜底 |
| D10 | watcher 全量缓存失效 → 刷新风暴 | 内置去抖 + 我方增量 diff 推送 + 事件合并 |

### 3.4 "提交卡死"四类归因（final_turn §六）

| 类型 | 根因 | 路线 A 下的处置 |
|---|---|---|
| ① Git 本身慢 | 大仓库 status/hooks/签名 | 内置上限保护 + 仓库调优建议（§7.3）+ 进度可见 |
| ② 等待无反馈 | 空消息静默等待、GPG/凭据等输入 | 前置校验拦截空消息；askpass 覆盖凭据；每阶段显示等待原因 |
| ③ 宿主主线程阻塞 | 同步子进程、大 diff 字符串处理 | 禁 `execSync/spawnSync`；解析渲染下沉 Webview；虚拟滚动 |
| ④ 双 provider 争抢 index | 两个控制器并发写 | 路线 A + 并存决策下不存在（单一写入口=内置 API） |

核心经验：**最常见的"卡死"不是慢，而是等待没有反馈**。把等待阶段显式化，体验即不再被误判为卡死。

### 3.5 竞品与差异化（final_turn §七，2026-11-13 实测）

- 头部：GitLens（5390 万+，blame/历史）、git-graph（1571 万+，已停更）——不与其比历史深度；
- IDEA 式提交工作台细分极小：ideagittool 759 安装、nifty-changelists 424、intellij-git-ext 4786——**尚未被有效占领，现有实现不构成护城河**；
- JetBrains 独立 Git Client 已停止开发（preview 至 2025-11-30）——短期无官方客户端化动作，窗口存在；
- 差异化落点：**把提交主线做深做稳**（批量勾选、多仓库编排、部分提交、可证明的性能指标），而非键位移植或图渲染。

### 3.6 许可与合规（final_turn §八 + 可行性报告 §11）

- intellij-community 许可 = JetBrains Open-Source Build Terms v1.3（代码 Apache-2.0 + 品牌/分发附加条款）；Rebased 及其衍生（ideagittool）继承该许可，**市场元数据不可靠（Open VSX 标 Apache-2.0 与仓库 LICENSE 不一致），以仓库文件为准**；
- **clean-room 自研**：只对齐行为，不复制 IDEA/GitJet/Rebased 源码与界面资源；AGPL 的 git-graph-libre 不可作拷贝源；
- 内置 Git 扩展 MIT：仅经公开 API 调用，行为复刻（如 blob 暂存做法）注明来源即可；
- 命名中性：主名 Git Batch Commit；IntelliJ/JetBrains 仅出现在描述与 keywords；不用 JetBrains 图标，统一 Codicon/自有设计；
- 依赖引入前 license-checker 扫描，不引入 copyleft 到核心分发物。

## 4. 总体架构（路线 A）

```
┌──────────────────────── VS Code Webview（React + Zustand）────────────────────┐
│ CommitPanel · RepoSection · ChangesTree(虚拟化/三态勾选) · CommitBox          │
│ CommitButton(分裂按钮) · BranchPicker · ProgressPanel · ResultPanel           │
│ Typed RPC Client（request/response/event/cancel，operationId 全链路）         │
└──────────────────────────────────┬────────────────────────────────────────────┘
                                   │ postMessage（结构化信封 v1，事件带 seq）
┌──────────────────────────────────┴────────────────────────────────────────────┐
│ Extension Host（TypeScript strict）                                           │
│  MessageGateway ── BatchOrchestrator（多仓库顺序提交/失败策略/结果聚合）      │
│       ├── GitApiAdapter ─── vscode.git getAPI(1)（激活/状态等待/repoId 映射） │
│       ├── InclusionModel ── 勾选 ⇄ index 映射（核心自建）                     │
│       ├── OperationTracker ─ UI 层状态机/进度/幂等                            │
│       ├── DiffService ───── toGitUri + vscode.diff + buffer/show              │
│       ├── HistoryService ── log 分页/过滤                                     │
│       ├── StashService ──── 四件套 API + 列表(MiniRunner)                     │
│       ├── ErrorMapper + TerminalBridge ─ 错误码→动作 + 终端兜底               │
│       └── MiniRunner(P1) ── 白名单：stash list / hash-object / update-index   │
│  Cache（分支短TTL/日志页/最近消息） · Diagnostics · EventBridge               │
└──────────────────────────────────┬────────────────────────────────────────────┘
                                   │
              内置 Git 扩展（vscode.git）→ 系统 Git CLI
    （进程治理 / 认证 / 锁重试 / watcher / 大仓库防护 全部由其承担）
```

**职责红线**：

- 所有提交语义操作走内置 API，不自建命令构造、不自建 watcher/进程锁/认证 UI；
- MiniRunner 是路线 A 唯一允许的自建进程调用，仅白名单命令，不承载提交语义；参数数组、stdin 显式关闭、输出上限、可取消；
- Webview 不解析 Git 输出；选择集以 `repoId + path + staged` 为键；
- 宿主禁止同步子进程调用；大 diff 内容按需分页，渲染下沉 Webview。

### 4.1 核心语义定死

**包含模型（InclusionModel）**：

- **勾选状态 = 暂存状态（checkbox = staged）**，对齐 IDEA 暂存区模式；
- 勾选未暂存/未跟踪/已删除 → `add([path])`（-A 语义）；取消勾选已暂存 → `restore([path], { staged: true })`；文件同时有未暂存变更时提示"取消勾选将同时取消暂存内容"；
- 提交 = `commit({ all: false })` 只提交 index——勾选与 index 强一致，不存在"未勾选却被提交"；
- Commit All = `commit({ all: true })`；仅 tracked 用 `all: 'tracked'`；
- 首次加载：tracked 默认全选，**未跟踪默认不选**（防误提交密钥/临时文件），可配置；
- 乐观更新：勾选立即翻转 UI → API 完成后以 `state.onDidChange` 回灌校准，失败回退；
- 提交前校验 `expectedStaged` 与 index 一致；提交中锁定包含集与消息。

**多仓库编排（BatchOrchestrator）**：

- 逐仓库顺序 commit；默认"任一失败即停"，可配置继续；
- 结果聚合：成功（oid/分支）/ 失败（错误码+动作）/ 跳过（原因）；
- Commit & Push：所有 commit 成功才逐仓库 push；部分 push 失败明确"本地已提交、远端未推送"；push 失败不回滚本地 commit；
- 取消语义如实限制：**只能取消后续仓库，不承诺中断进行中操作**；任何状态必须能回 Idle，不允许永久 spinner；
- 同仓库提交中禁用按钮（幂等）；不同仓库可并行（内置每仓库独立锁）。

**错误呈现（ErrorMapper + TerminalBridge）**：

- 三层：一句话摘要（错误码映射）→ 可展开详情（码/命令名脱敏/耗时 + "查看 Git 输出"按钮调 `git.showOutput`）→ 恢复动作；
- 每个错误至少一个可操作动作：钩子失败→"跳过钩子并重试"（二次确认）；身份缺失→打开设置；冲突→打开合并编辑器；锁→手动重试；推送被拒→引导 pull/rebase；
- **所有错误兜底 = "在终端重试"**：`sendText` 脱敏等价命令，不自动回车，不含凭据；
- GPG/pinentry 无专门错误码 → GenericError + 查看输出 + 终端重试；P2 提交前预检 `commit.gpgsign`。

### 4.2 通信协议要点

- 信封 `{ v, id, method, repoId, params }`；响应必达（ok/error），错误枚举化；
- **不设统一超时**（askpass 已消灭等输入场景；进度可见即可）；
- 事件带 `seq`，Webview 检测丢帧请求全量刷新；进度事件节流 10–20 次/秒；
- 单次 IPC payload ≤ 1MB，超出分片/按需；禁止一次推送全仓库文件内容。

### 4.3 Diff 与部分提交

- Diff：`api.toGitUri(uri, ref)`（`''`=工作区、`~`=index、`HEAD`）+ `vscode.diff`；标题标注两侧（如 `path (Working Tree ↔ HEAD)`）；重命名用 `originalUri/renameUri`；删除侧空文档标注；二进制/大文件前 8KB 探测 + 阈值（默认 2MB），超限显示元数据 + "仍要打开"；
- Hunk 级暂存（P1）：diff 编辑器选中行 → 重组内容 → MiniRunner `hash-object -w --stdin --path` → 查 HEAD 侧 mode → `update-index --add --cacheinfo` → `state.onDidChange` 校准。**不走 patch/apply --cached**（CRLF 风险）；二进制不支持，明确报错优于静默错误。

### 4.4 技术选型与目录

- TypeScript strict + esbuild；Webview React + Zustand（虚拟列表）；测试 Vitest + @vscode/test-electron + Playwright；
- 目录按可行性报告附录 B：`src/{protocol,adapter,core,services,ui,webview,test}`，按阶段增量创建，不一次建齐。

## 6. 交互规则要点

- 按钮禁用条件（无消息/无包含/提交中/有冲突）**必须显示原因**（tooltip 或按钮下提示）；

- 分支切换：QuickPick（搜索/最近/Local/Remote 分组/当前置顶）；脏工作区提示，Stash & Switch（P1）；
- Diff 入口：单击/双击开工作区侧 diff；右键 Show Diff / Show Staged Diff / Open File / Rollback / Stage / Unstage / Copy Path；
- 危险操作（rollback、删分支、drop stash、强推、amend 已推送）全部二次确认并显示影响；不自动执行 `reset --hard` / `checkout -- .` / `clean -fd`；
- 面板布局：仓库/分支头 → 消息区（历史/模板/统计）→ 分组变更树 → 底部 Commit 分裂按钮 + 进度/结果区（详见可行性报告 §5.1）。

## 7. 性能预算与度量

### 7.1 验收指标（合并两份文档，P95 口径）

| 指标 | 目标 | 条件 |

| UI 长任务 | 无 > 100ms | 提交/刷新期间 |
