# 性能标定报告（#25，2026-11-17）

真实编辑器端到端标定：headless VS Code 1.146.0（xvfb）+ 已打包 vsix（含批量乐观更新），CDP 驱动测量。
夹具：`test/perf/make-fixtures.mjs` 生成 repo10k（10000 个 tracked-modified，含 batch100/ 目录 100 文件）、repo50k（50000）、repoLog（350 commits）。
工作区设置：`git.statusLimit=100000`（放开内置截断以测真实 50k）、`gitBatchCommit.commit.defaultSelectAll=false`（隔离首屏自动暂存风暴）、`gitBatchCommit.log.pageSize=300`。
驱动：`test/perf/perf-run.mjs <10k|50k>`（场景测量）、`test/perf/perf-attribute.mjs <repo>`（归因：SCM badge = 内置刷新完成时刻，面板 DOM = 我们渲染时刻；ext-host inspector setTimeout 漂移探针；Performance.getMetrics 堆；longtask observer）。
测量前设稳态门：badge > 0 且间隔 800ms 两次读数一致，避免初始扫描污染窗口。原始 `git status --porcelain=v1 -z -uall` 对照：10k = 0.16s，50k = 0.44s。

## 1. 结果 vs §7 预算

| 指标 | 预算 | 10k 实测 | 50k 实测 | 判定 |
|---|---|---|---|---|
| 面板首屏（冷） | ≤ 800ms | 3715ms | 11816ms | **不达**（归因见 F17） |
| 单文件变更刷新 | ≤ 150ms | 1208–2393ms | 280–6996ms | **不达**（内置刷新链主导；我们层 ≈0） |
| 暂存/取消 100 文件 | ≤ 500ms | 51ms（感知） | — | **达**（乐观更新；git 后台 ~1.4s 对账） |
| 全选暂存（感知） | — | 28ms | — | 乐观更新即时响应 |
| 提交反馈（点击→结果+刷新） | 万文件 ≤ 1.5s | 2150ms | — | **不达**（F19） |
| 宿主事件循环阻塞 | ≤ 50ms | 3ms | 4–5ms | **达** |
| 日志首屏 300 条 | ≤ 400ms | 53ms | — | **达** |
| Webview 内存 | ≤ 150MB @50k | 30MB | 53MB（滚底后同） | **达** |
| UI 长任务 | 无 > 100ms | 最大 88ms | 104/149/112ms | 10k 达；**50k 不达**（F18） |

提交额外开销（≤300ms，不含 git/钩子）无法与 git 耗时直接分离；编排全异步、零同步子进程，ext-host 漂移 3–5ms 间接佐证我们层开销小。IPC 字节未埋点，本轮不报。

## 2. 归因要点

- 稳态单文件刷新：面板 DOM 更新与内置 badge 更新同源于 built-in `onDidChangeState`；多次测量中面板比 badge 早 102ms–6.8s（badge 等待 numstat 等后续命令），**我们推送/渲染层附加延迟 ≈ 0**。延迟地板 = 内置 watch 去抖 + status + numstat 链（10k ≈ 1.3–1.4s；50k 全链 ≈ 7s，但状态事件早到，感知可低至 280ms）。
- 冷启动：Page.reload 重启 ext-host；内置激活+仓库发现+扫描 10k ≈ 3.7s 内状态可用（面板首屏），badge 全链 6.9s；50k 面板 11.8s / badge 16.7s。原始 git status 仅 0.16/0.44s → 成本在内置多命令管线与宿主启动，非 git 本身。
- 50k 长任务 104–149ms：每次状态推送 `buildTree`+`flattenTree` 全量物化 50k 行对象（虚拟列表只渲染 ~40 行但行数组全量构建）。

## 3. 本轮已做修改

- **批量勾选乐观更新**（`src/webview/store.ts` `stagePaths`）：目录/整组勾选即时置 staged，失败回滚，状态事件对账（与单文件 `toggleStaged` 同模式；§7.1 既定策略）。暂存 100 感知 1594ms → 51ms。新增 `test/unit/storeOptimistic.test.ts` 4 用例（即时性/冲突与未选不动/失败回滚/乐观取消）。
- 验证：65 单元 + 31 集成全过；vsix 重打包安装后实测。

## 4. 发现与建议（待决策，未擅自实施）

- **F16**：内置 `git.statusLimit` 默认 10000 截断状态；产品继承该上限（即"内置大仓库上限保护"）。50k 全量需用户调高设置；建议 UI 在截断时提示"仅显示前 N 个变更"。
- **F17**：Route A 以 built-in 状态事件为源，§7 的 150ms 刷新 / 800ms 冷启动预算在该架构下不可达（地板 1.3s+）。建议：修订预算为"感知延迟"口径（乐观更新已覆盖勾选类），或 P2 评估 MiniRunner 自有 status 快路径（Route C 混合）替换事件源。
- **F18**：50k 长任务超 100ms。建议 P2：懒物化 flatten（只物化可视切片，行总数用计数推导），预计消除 >100ms 长任务。
- **F19**：提交结果面板等 post-commit 刷新完成才显示（2150ms）。建议：commit 成功即发结果，刷新异步对账，感知可降至 ~0.5s。
- **F20**：`defaultSelectAll=true` 首屏对全部 tracked 变更自动 `git add`（50k 时启动即重操作）。本轮测量已关闭；建议大仓库（如 >5k 变更）跳过自动暂存或改为询问。
