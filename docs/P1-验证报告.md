## 1. 交付清单

### P1-1 提交选项补全
- **Sign-off**：`CommitOptions.signoff` 贯通 orchestrator → 内置 `commit()`；UI 选项行新增 Sign-off 复选框；集成检查 20 验证 `Signed-off-by:` trailer 真实落盘。
- **commit.template**：`commit.template` 协议；宿主读取顺序 `getConfig('commit.template')`（仓库级）→ `getGlobalConfig`（全局）；`~` 展开为 home、相对路径按首个仓库根解析；64KB 上限、剥离 `#` 注释行、trim；面板初始化且消息为空时自动载入。
- **author / cleanup 延后**：内置 API `CommitOptions` 不含这两项（见 §4 遗留），不做 MiniRunner 绕过提交主流程（提交必须走内置 API 以保留钩子/凭据/签名语义）。

### P1-2 MiniRunner 白名单执行器（`src/core/miniRunner.ts`）
- 结构化请求联合类型，**调用方永远不传 argv**：`update-index`（≤1000 条 `mode,oid,path`）、`ls-files`、`stash-list`、`branch-rename`、`diff-worktree`。
- `validatePath`：禁前导 `-`/`/`、NUL、反斜杠、`..`，长度 ≤4096；`validateBranchName`：git 分支名规则子集（禁 `..`、`@{`、控制字符、结尾 `.`/`/`/`.lock`）。
- 每仓库串行队列；`index.lock` 冲突指数退避重试（5 次，100·2^n ms）；30s 超时；`GIT_TERMINAL_PROMPT=0`；只读命令 `GIT_OPTIONAL_LOCKS=0`；stderr 截断 8KB；错误映射 `LOCKED/GENERIC/GIT_NOT_FOUND`。
- 全部经 `spawn(git, argv[])`，无 shell 拼接（安全规则 §1）。

### P1-3 Hunk 级暂存（C3 blob 方案）
- `src/core/hunkDiff.ts`（纯函数）：`parseHunks`、`splitLines`（保留末尾换行语义）、`applyHunks`（上下文逐行校验，漂移抛 `HUNK_CONFLICT`）、`syntheticAddHunk`（未跟踪整文件）、`isBinaryPatch`。
- `src/services/hunkService.ts`：
  - 暂存 = 读 index 基 blob（`buffer('', path)`，见 F13）→ 应用选中 hunk → `hashObject`（内置 API）→ MiniRunner `update-index --cacheinfo`；mode 取自 `ls-files` 或工作区执行位。
  - 取消暂存 = HEAD blob + 保留 hunk（补集）；结果 == HEAD 时走 `restore(paths,{staged:true})`。
  - index→worktree patch 经 MiniRunner `diff-worktree`（见 F12）；未跟踪判定经 `ls-files`（见 F14）。
  - 每仓库串行锁；文件 2MB / patch 8MB 上限。
- UI：文件行 Hunk 按钮 → 浮层逐 hunk 勾选（默认全选）、彩色行预览（2000 行截断）、全选/全不选。
- 验证：纯函数与真实 `git apply` 交叉对照（单测）；集成 17–19 在真实编辑器内断言 index blob 精确内容、工作区未被触碰、取消暂存回 HEAD、未跟踪合成 hunk。

### P1-4 Stash
- `src/services/stashService.ts`：`getStashes()` 优先（API 已暴露），回退 MiniRunner `stash-list` 三元组解析；create（消息 trim + 500 字上限，`-u`/`-S` 可选）；apply/pop/drop 均 `assertIndex`（0..10000 整数）。
- **drop 永远携带 index**（上游 `dropStash()` 无参 = `stash clear`，见类型注释警示）。
- 干净仓库 create 不产生 stash 也不报错（F15）——UI 列表刷新后自然为空。
- UI：仓库头 Stash 按钮 → 浮层（创建行 + 条目列表）；**弹出/丢弃均内联二次确认**，丢弃按钮 danger 样式。

### P1-5 分支管理增强
- 宿主：`branch.create`（名称校验 + `checkout??true`）、`branch.delete`（**禁止删除当前分支**；`force=false`，未合并分支由 git 拒绝）、`branch.rename`（MiniRunner `branch -m`）、`branch.compare`（`DiffService.openBranchCompare`：merge-base → `base..other` 多文件 Diff，空差异提示）。
- `repo.pull` / `repo.push`：特性探测；push 拒绝 detached HEAD，upstream 存在时不重复 `--set-upstream`；OperationTracker 新增 `pull/push` kind，面板显示"拉取中…/推送中…"。
- UI：分支胶囊 → 分支管理浮层（创建并切换、逐分支 对比/重命名/删除；重命名内联输入 + Enter 确认；删除内联二次确认；当前分支隐藏 对比/删除）；仓库头新增 拉取/推送 按钮（操作进行中禁用）。
- 错误经 `toProtocolError(err,'branch'|'pull'|'push')` 附带白名单 `terminalCommand`（仅 `git <子命令>` 形式，无参数回显）。

### P1-6 提交日志分页/筛选
- `log.list` 协议：`skip/author/grep`；宿主 `repo.log({maxEntries: pageSize+1, skip, author, grep})`，多取一条判定 `hasMore`；`gitBatchCommit.log.pageSize` 设置（10..500，默认 50）。
- grep 由内置 API 以 `--extended-regexp --regexp-ignore-case` 执行，用户输入仅作为 argv 值（无 shell）。
- UI：仓库头 日志 按钮 → 浮层（作者/消息筛选输入 + Enter 触发、条目 = 短 hash + 首行消息 + 作者/时间、点击 → 既有 `commit.show` 多文件 Diff、加载更多追加）。

### P1-7 冲突增强
- 冲突文件行：**合并编辑器**（探测 `git.openMergeEditor` 命令，失败回退强制 Diff）+ **标记解决**（= 暂存该文件，git 语义即 resolved）。
- `merge.abort`：`mergeChanges` 非空 → `mergeAbort()`；否则 `rebaseCommit` 存在 → `rebaseAbort()`；否则报错"没有进行中的合并/变基"。UI 仓库头出现"中止合并"（danger）→ **全局二次确认浮层**（丢弃进度警示）。
- 集成 27/28 制造真实合并冲突与变基冲突：abort 精确恢复操作前内容与分支 tip；resolve = 写解决内容 → stage → commit 完成合并。

### P1-8 键位/设置/可访问性
- 新命令 `gitBatchCommit.commit`（命令面板 + 键位）；键位 `Ctrl/Cmd+Alt+C`（提交）、`Ctrl/Cmd+Alt+R`（刷新），**when 子句统一为 `gitBatchCommit.panelFocused`**——该上下文键由 webview focus/blur 经 `ui.focus` 协议 → `setContext` 维护，避免与编辑器键位全局冲突。
- 宿主命令 → `ui.command` 事件广播 → webview 执行 commit（与面板内 Ctrl+Enter 同一入口，含 noVerify 确认门）。
- 新设置 `gitBatchCommit.log.pageSize`。
- 可访问性：变更树 `role="tree"` + 行 `aria-label`（路径/暂存态/快捷键提示）；文件/目录行可聚焦（tabIndex），**↑/↓ 在行间移动焦点，Enter/Space 切换暂存（目录为折叠），D 打开 Diff**；复选框全部带 aria-label；焦点行 focusBorder 描边；**Escape 逐层关闭浮层**（中止确认 → Hunk → Stash → 日志 → 分支 → 历史 → 错误条）。

### P1-9 测试扩充
- 单元 32 → **57**：新增 `miniRunner.test.ts`（11，含真实 git 往返：update-index/ls-files Unicode/stash-list/branch-rename/串行/错误）、`hunkDiff.test.ts`（14，含与 `git apply` 交叉验证、无尾换行、二进制标记）。
- 集成 16 → **29**（见 §2）；夹具新增 repoA 40 行 hunk 基线文件（3 个远距 hunk）。

## 3. 新增 API 漂移发现（F12–F15，stable 1.146.0 实测）

| # | 发现 | 影响 | 对策 |
|---|---|---|---|
| F12 | `diffIndexWith(ref, path)` 实际执行 `git diff --cached <ref> -- <path>`（**不是** index→worktree）；`diffWith(ref, path)` = `git diff <ref> -- <path>`；空串 ref → `fatal: bad revision ''`（内置 spawn 原样透传 argv，不做 falsy 过滤） | 无法经 API 取 index→worktree patch | MiniRunner `diff-worktree`：`git diff --no-ext-diff --no-textconv -- <path>`；staged 侧用 `diffIndexWithHEAD(path)` |
| F13 | `buffer(ref, path)` 原样执行 `git show --textconv ref:path`：`''` → `:path`（index blob，可用）；`'~'` **不**被特殊处理（报 "Could not show object"），尽管 `toGitUri('~')` 在编辑器 provider 中有效 | index 基 blob 读取方式与文档直觉不符 | HunkService 统一 `buffer('', relPath)` 读 index；HEAD 用 `buffer('HEAD', …)` |
| F14 | `git.untrackedChanges` 默认 `'mixed'` → `state.untrackedChanges` 恒空，未跟踪文件混在 `workingTreeChanges`（status 7） | 依赖 untrackedChanges 判未跟踪会漏 | `ls-files -s -z -- <path>` 输出为空即未跟踪（MiniRunner） |
| F15 | 干净仓库 `git stash push` exit 0（"No local changes to save"），API 不抛错、不产生 stash | create 后不能假定有条目 | UI 以刷新后的列表为准；集成 23 显式断言该语义 |

（F8–F11 见《P0-验证报告》；F8 的 `diffBetweenWithStats2` 原始 range 用法在 P1 分支对比/日志详情中继续复用。）

## 4. 安全约束复核（agent_rules / 方案安全节）

| 约束 | 落实 |
|---|---|
| 禁止 shell 拼接用户输入 | MiniRunner 仅接受结构化请求 → `spawn(git, argv[])`；路径/分支名白名单校验；日志 grep/author 仅作 argv 值 |
| 终端重试仅白名单 sanitized 命令、不自动回车、不含凭据 | `toProtocolError` 只产出 `git <子命令>` 形式；TerminalBridge 既有白名单不变 |
| 日志/诊断脱敏 | 诊断环仅方法名/耗时/错误码；stderr 截断且不回显文件内容 |
| 危险操作二次确认 | 删除分支（内联确认 + force=false + 禁删当前分支）、丢弃 stash、弹出 stash、中止合并/变基（全局确认浮层）、noVerify（既有）；amend 不自动强推（P0 决策延续） |
| 不自动 reset --hard / checkout -- . / clean -fd | 无任何此类调用；abort 仅经内置 `mergeAbort/rebaseAbort`（git 自身安全语义） |
| 未跟踪默认不勾选 | `selectUntracked` 默认 false 延续；hunk 合成暂存需用户显式操作 |
| 强推仅显式 + 双确认 | P1 未新增强推入口；push 不带 force |

## 5. 遗留与后续（P2 / 手动）

1. **author / cleanup 提交选项**：内置 `CommitOptions` 未暴露；若 P2 需要，评估 MiniRunner 之外的方案（不绕过内置 commit 主流程）。
2. **F5 视觉手动验收**（P0 延续）：headless 无法截图验收浮层布局/主题适配，需真实编辑器 F5 走查（分支管理、Hunk、Stash、日志、中止确认五个浮层 + 键盘导航）。
3. **真实编辑器 10k+ 文件性能标定**（P0 延续）：纯树管线基准已达标，端到端渲染待标定。
4. 合并编辑器依赖 `git.openMergeEditor` 命令存在性（探测 + Diff 回退已覆盖）；不同 VS Code 版本命令名若变化仅影响回退路径。
5. 日志视图未做虚拟滚动（每页 ≤500，追加分页；超大仓库如需全量浏览再评估）。
